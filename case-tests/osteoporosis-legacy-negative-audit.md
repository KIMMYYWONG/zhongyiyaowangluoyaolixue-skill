# “Osteoporosis”旧数据负向审计

## 结论

这套数据不作为有效疾病案例继续跑下游模块。原因不是脚本不能读取，而是疾病标签与文件内容缺少一致性证据；继续计算会产生形式完整、语义可能错误的结果。

## 发现

- 配置/汇总文件把疾病写为 `Osteoporosis`。
- 多个疾病来源文件的首批记录集中在 TTN、FLNC、MYH7、心肌病或心血管相关条目。
- OMIM 类文件首条记录与 `1p36 deletion syndrome` 相关。
- 现有导出没有稳定的 disease-name 字段或查询截图，无法确认这些文件确实由 Osteoporosis 查询产生。

## Skill 应执行的门禁

1. 每个疾病来源必须记录数据库、查询词、物种、查询日期、原始文件和证据截图/URL。
2. 若文件缺少 disease-name 字段，必须用查询日志或截图补充来源证明。
3. 发现标签与内容疑似错配时，停止下游交集、PPI 和富集，不自动改病种，也不根据基因列表反推病名。
4. 数据拥有者确认来源后，才可把该目录转换成正式回归案例。

该负向案例证明来源门禁能够阻止“能运行但病种可能错误”的分析。
