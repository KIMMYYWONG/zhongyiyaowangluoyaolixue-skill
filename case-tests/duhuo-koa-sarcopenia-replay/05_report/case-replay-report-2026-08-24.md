# 独活寄生汤—KOA 与 Sarcopenia 网络药理学回放报告

## 1. 本次验证对象

- 方剂：独活寄生汤。
- 疾病口径：先分别整理 KOA 与 Sarcopenia 疾病靶点，再求两种疾病的交集，最后与药物靶点求交集。
- 目的：验证 `network-pharmacology-research` Skill 的框架、脚本、QC、异常处理和可复现性，不把当前案例写死成固定 15 味药或固定疾病。
- 冻结日期：2026-08-24。

## 2. 主要结果

| 环节 | 结果 |
|---|---:|
| 旧多工作表成分—靶点关系 | 23,611 条 |
| 药物唯一靶点 | 2,408 |
| KOA 广义疾病靶点 | 2,072 |
| Sarcopenia 广义疾病靶点 | 1,303 |
| KOA∩Sarcopenia | 286 |
| 药物∩共病靶点 | 167 |
| PPI 有效节点 | 157 |
| 严格核心靶点 | 58 |

疾病数据库输入实际包含 CTD、DisGeNET、GeneCards 和 OpenTargets；DrugBank 与 OMIM 当前没有可复核导出，因此被明确记录为缺失，没有伪造补齐。

## 3. 核心靶点差异

旧案例保留了 60 个核心靶点；严格执行“Betweenness、Closeness、Degree 均大于各自中位数”后为 58 个。Degree 中位数为 13，LPL 与 NOS3 的 Degree 恰好为 13，只满足“等于”而不满足“大于”，因此本流程将二者排除。脚本、阈值表和差异说明均保留，避免为了复刻旧结果而修改规则。

## 4. GO/KEGG

交集靶点与核心靶点均分别进行了 GO 和 KEGG 分析，均使用 clusterProfiler：

- 交集靶点：167/167 成功映射；GO 全部 4,834 条、原始 P<0.05 为 2,850 条；KEGG 全部 142 条、原始 P<0.05 为 64 条。
- 核心靶点：58/58 成功映射；GO 全部 3,730 条、原始 P<0.05 为 2,517 条；KEGG 全部 103 条、原始 P<0.05 为 66 条。
- GO 展示前 15 条，KEGG 展示前 30 条；全量结果没有因绘图截断而丢失。

本机在线 `enrichKEGG` 因 SSL 连接失败。流程没有转用 Metascape，也没有静默跳过 KEGG，而是使用 2026-08-17 冻结的官方 KEGG PATH 映射与名称快照，通过 `clusterProfiler::enricher` 计算。输出中保留 `orgdb_path` 方法标签和快照日期，可重复、可追踪。

## 5. 网络与图形

- 成分—靶点—疾病网络同时生成 `filtered` 与 `complete` 两种 shared 成分归属版本；两者 QC 均通过。发表前必须明确选择一种，不能混用。
- `filtered`：383 个成分、103 个 shared 成分、3,390 条边、567 个节点。
- `complete`：383 个成分、105 个 shared 成分、3,394 条边、567 个节点。
- 核心靶点—通路网络：43 个基因、30 条展示通路、265 条边。
- 核心成分—核心靶点—通路桑基图保留 9,763 条完整三元组；展示版限制为 10 个成分、15 个基因和冻结的 30 条通路，以保证可读性。PNG 为 600 dpi，另有矢量 PDF。

## 6. 本轮 Skill 改进

1. 新增旧式“每味药一个 sheet”工作簿适配器，要求显式 sheet—药物映射，不按 sheet 顺序猜测药名。
2. 新增通用共病疾病交集模块及来源追踪表。
3. 新增文件签名检查，能识别扩展名为 `.csv`、实际为 XLSX ZIP 的伪 CSV。
4. 修复 KEGG 空结果导致脚本中断的问题，空结果也能输出 QC。
5. 新增 `online`、`rest_snapshot`、`orgdb_path` 三种明确 KEGG 模式。
6. 对富集结果中的 `geneID` 进行确定性排序，两次稳定运行的 12/12 个关键 CSV 哈希一致。
7. 核心靶点严格执行三项指标均 `> median`，并输出阈值与保留标记。
8. Stage 08 显式声明预期的 many-to-many 连接，去除误导性警告。
9. 桑基图显示通路名称，增加过密告警，同时分离完整三元组与展示子集。

## 7. 三轮检查结论

- 第一轮：模块级运行与人工核对，发现并修复伪 CSV、KEGG 空表、核心阈值等问题。
- 第二轮：在独立输出目录重复关键模块；除富集结果 `geneID` 顺序外其余关键结果一致。
- 第三轮：确定化 `geneID` 后再次运行；Stage 05 的 12/12 个选定 CSV 哈希一致，关键计数与主输出一致。

另外，两味药 Stage 01 回归案例仍用于验证新数据模板和 DNP 待补逻辑。另一套标注为 Osteoporosis 的旧数据因多个疾病文件内容与病种标签缺少一致性证据，被来源门禁拦截为负向案例，没有强行生成“看起来合理”的下游结果。
